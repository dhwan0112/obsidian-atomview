# Format support

All formats below have synthetic parsing tests and have rendered in the offline headless Mol* harness. The five format families have also rendered in actual Obsidian 1.14.4 file tabs through the official CLI; this smoke coverage does not establish every variant or large-file performance. See TEST_REPORT.md.

| Format | Supported | Explicit limits / behavior |
|---|---|---|
| LAMMPS text dump | Named/reordered columns; orthogonal and restricted triclinic bounding bounds; nonzero origin; x/y/z, xs/ys/zs, xu/yu/zu, xsu/ysu/zsu; exact string IDs/timestep; image flags, q, forces, velocities, numeric custom columns | Coordinate priority **xu, xsu, x, xs**. Current set and multiple-set warning displayed. Original columns preserved. No image shift is added to already-unwrapped coordinates. General triclinic, binary/compressed input rejected. No physical time/units inferred. |
| LAMMPS data | atomic/charge/full from explicit choice or Atoms hint; actual bounds without dump correction; tilt, Masses, charge, molecule ID (including zero), image flags | Ambiguous/unsupported style and conflict with hint rejected. Bonds and additional sections preserved raw with interpretation warnings, not rendered. PBC/units unknown. Masses never establish an element. |
| XYZ | Single and multiple frames, species and Cartesian coordinates | No cell invented. Species not recognized as an element remain type labels. Files without IDs explicitly assume row-order correspondence. Unit is not asserted. |
| Basic extended XYZ | Quoted Lattice/Properties/pbc headers, species/pos, declared numeric/string scalar/vector properties, logical 0/1 encoding with declaration retained, precision-safe integer IDs including zero | Lattice flat order is ax ay az bx by bz cx cy cz; stored as row vectors a,b,c. Missing/invalid required declarations cause errors, not a plain-XYZ fallback. Per-atom strings containing spaces/quoted atom-row fields are unsupported and fail column validation. No origin convention or extra metadata semantics is invented; header metadata retained. Numeric vector coloring requires explicit component/magnitude. |
| PDB | Mol* PDB tokenizer reused; Float64 fixed-width coordinates, original serial, explicit element, atom name, residue, chain, insertion code, altLoc, occupancy, B factor, CRYST1 cell; multiple MODEL frames | All deposited models are available as frame indices, with original model number in metadata. Missing element remains unknown. No inferred bonds, assembly, alternate-conformer selection or symmetry expansion. Truncated records/models rejected. |
| coreCIF | Mol* CIF parser; cell, fractional coordinates transformed in Float64 using Mol* crystallographic matrix; site label, explicit element, occupancy/disorder and raw categories | Exactly one data block. **Asymmetric unit only**, not a symmetry-expanded crystal. Occupancy/disorder retained, sites displayed as listed. No supercell or symmetry expansion. |
| mmCIF | Mol* CIF parser; Cartn coordinates, exact ID, explicit element, atom/residue/chain fields, occupancy and raw categories | First deposited model only; original model number retained, limitation displayed. One data block. Cartesian atom_site input required; fractional-only mmCIF is not implemented. No symmetry/assembly expansion. |

Atom IDs remain separate from array indices. Duplicate IDs are rejected per frame, missing IDs are flagged, changing ID sets are flagged. Frames are displayed discretely without interpolation or inferred identity for ID-free inputs. Selected IDs follow reordered LAMMPS rows correctly.

Positions and cells must be finite; degenerate cells, malformed columns, truncated frames and count mismatches are rejected. Missing scalar properties never become zero. The display uses Float32 mesh buffers without mutating source Float64 coordinates. Very large absolute coordinates may lose rendering precision; no such large-coordinate rendering benchmark has been performed.

CIF/PDB lengths follow their specifications (angstrom). LAMMPS units are unknown and XYZ units are not asserted. Cell PBC is unknown unless explicitly supplied in a supported source field. Wireframes represent only an actually parsed cell. No physical MD time is displayed.

## Disk-backed LAMMPS scope (2026-10-17 update)

Uncompressed text `.lammpstrj` or explicit `lammps-dump` now uses byte indexing and lazy frame reads: ≤2 GiB, ≤100,000 frames, ≤50,000 atoms/frame, ≤16 MiB/frame. No whole-trajectory atom-record limit applies to this path. Indexing checks frame structure and row counts; finite values, duplicate IDs, exact cell transforms and properties are validated when the frame is accessed. An indexed file is not a claim that all its atom values have been validated. A malformed tail is an explicit index error. Changing sources must be reloaded.

XYZ/extended XYZ, PDB/CIF and LAMMPS data still use bounded in-memory readers (16 MiB/file, 500 frames, 250,000 atom records). Compressed/binary/general-triclinic dumps, growing-file live mode and persisted indexes remain unsupported. Selected external files require explicit read-only registration; opaque source IDs do not grant arbitrary external path access.
